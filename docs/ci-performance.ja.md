# CIの実行時間

[English](ci-performance.md) | [日本語](ci-performance.ja.md)

必須チェック名、7種類のネイティブ実行ファイル、モデルの探索上限、安全性・活性の性質、実コードの変異に対するアサーションを維持したまま、重複実行を減らし、独立したテストを並列化しています。

## 形式検証

`verify:<area>:selftest` は正常系の検証もすべて含みます。CIではこのコマンドを1回実行し、`result.json` と `selftest-result.json` の両方を保存します。変異を実行せずに正常系だけ調べる場合は、従来どおり `verify:<area>` を使えます。

同時に検査できる性質は、TLCの状態グラフ探索を共有します。成功時も性質ごとの結果を残します。TLCは最初の違反で停止するため、まとめた検査が失敗した場合はすべての性質を個別に再実行します。未検査の性質を成功と扱いません。起動失敗、完了出力の欠落、リプレイ件数の不足、実行環境の異常も失敗になります。

送信のselftestは正常な実コードのリプレイ10件、受信は8件を、それぞれ1回実行します。追加した送信の2件は、Objectの引き継ぎをまたぐ古い無効化の書き込みと送信許可の競合を検査します。その後、変異ごとに新しいテスト実行を開始します。送信の変異では対応するリプレイファイルだけを選び、ファイルごとの分離を維持します。選択されたテスト件数が正常系の対応するテストと一致し、変異によって指定した全ケースのアサーションが失敗することを要求します。成功済みの検証結果はキャッシュしません。

Webhook追加前のモデルでは、変更前と探索を共有した変更後で次の状態グラフが一致しました。

| モデル | 異なる状態数 | 生成状態数 | 最大深さ |
| ------ | -----------: | ---------: | -------: |
| 送信   |      130,184 |    389,783 |       71 |
| 受信   |        3,104 |     10,877 |       28 |

有限の範囲に対するモデル検査であり、プログラム全体の正しさの証明ではありません。仮定、上限、コードとの対応、限界は[形式検証](formal-verification.ja.md)を参照してください。

## テストとツールの準備

`mise run test` はWorkerとBunのテストを独立したプロセスで並列実行します。既存の全テストに加え、冪等キーの自動採番の回帰テストも登録しています。miseを使わない環境では `bun run test` が同じテストを順番に実行します。

CIの各ジョブは必要なツールだけをインストールします。PRの実行ファイルビルドとnpm互換性検査では、バージョンを固定したツールのダウンロードをキャッシュします。リリース用の実行ファイルビルドと公開処理は、従来どおりキャッシュを使いません。依存関係は固定されたロックファイルでインストールします。実行ファイルの再現性、各環境のスモークテスト、署名、attestation、依存関係・セキュリティ検査、リリース検証も維持します。

## 計測方法

変更前後の比較では同じモデルと探索上限を使います。ローカルの実行時間と、GitHubランナーの待ち時間・準備時間は区別します。

```sh
/usr/bin/time -p mise run verify:outbound:selftest
/usr/bin/time -p mise run verify:inbound:selftest
/usr/bin/time -p mise run verify:attachments:selftest
/usr/bin/time -p mise run test
```

調整前に観測したGitHub Actionsのジョブ全体は、送信の形式検証193秒、受信72秒、添付45秒、テスト83秒でした。過去の計測値であり、今後のランナーで同じ時間になることを保証するものではありません。

2026-10-26のローカル計測では、探索上限を固定し、検証結果のキャッシュを使わず、各コマンドを1回実行しました。変更前は正常系とselftestを別々に実行し、変更後のselftestは両方を含みます。

| 形式検証の対象 | 変更前の正常系 + selftest | 統合したselftest | 短縮率 |
| -------------- | ------------------------: | ---------------: | -----: |
| 送信           |                   89.41秒 |          24.83秒 |    72% |
| 受信           |                   27.84秒 |          13.25秒 |    52% |
| 添付           |                   20.67秒 |          18.06秒 |    13% |

Webhookのモデルを追加する前の既存モデルに対する計測値です。CIランナーの性能や、その後の実装・モデルの変更によって合計時間は変わります。
