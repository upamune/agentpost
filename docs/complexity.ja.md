# コード複雑度の検査

[English](complexity.md) | [日本語](complexity.ja.md)

[moznion/cccc](https://github.com/moznion/cccc) で、認知的複雑度（制御フローの追いにくさ）と循環的複雑度（独立した制御フローの経路数）を測定します。`mise.toml` で 1.8.4 とプラットフォーム別リリースのチェックサムを固定し、mise が利用可能な GitHub artifact attestation も検証します。保守性の指標であり、脆弱性の検出や正しさの証明ではありません。

## ローカル実行

```sh
mise install
mise exec -- bun install --frozen-lockfile
mise run complexity
# ポリシー判定を行わず、cccc 本来の全 JSON 測定結果を表示:
mise run complexity:report
# 通常の検査・形式検証と合わせて実行:
mise run ci
```

明示した `cccc.toml` を使い、`src/`、`scripts/`、`verification/` を検査します。複雑度チェッカー自身と形式検証の実行ツールも対象です。大きな合成ケースを含む TypeScript テスト（`*.test.ts`、`*.bun.ts`、`*.fuzz.ts`）は対象外とし、別途テストします。他のディレクトリ、運用者の非公開ファイル、依存関係、ビルド出力、未対応拡張子も対象外です。ゲートではキャッシュ、上位 N 件・最小値による絞り込みを使いません。

## 上限と解消した負債

`complexity-baseline.json` で、ネストした関数も含め、**関数識別子ごとに認知的複雑度8・循環的複雑度6**を上限とします。**例外はゼロ**です。以前の15/10基準では、製品リビジョン `59dfd626440963a76ac72edf6075975f9caa722c` に既存の超過が28関数あり、CLI の `main` は90/56でした。最初の整理で例外をなくし、上限を12/8へ下げました。次の整理では8/6を超える44関数を改善し、現在の最大値は8/6、認知的複雑度の95パーセンタイルは5になっています。削減のために対象ディレクトリを除外する変更はしていません。

CLIコマンド、DNS診断、購読状態、JSONサイズ計算、メールと認証の条件を、役割が明確な小さな処理へ分けました。コマンドのリクエスト、TXTデコード、MCPのエラー対応を回帰テストで確認し、送受信の状態遷移は形式モデルと実コードの変異検査で確認します。キューハンドラーの回帰テストでは、成功と失敗が混在するバッチ、再試行間隔の上限、重複配信のackとイベントも確認します。

識別子は、区切りを正規化したパス、外側の関数の列、種類、名前、同名の兄弟関数の出現順を組み合わせます。行番号だけの移動では変わりません。無名関数や同名メソッドは構造上の識別子であり、意味や暗号学的な識別を保証しません。挿入・並べ替え・改名・移動の際は、別のコードに古い上限を割り当てないよう差分を確認してください。指標はこのレビューを代替しません。

- 新しい識別子には既定の上限を適用し、ファイル全体の最大値を継承させません。
- 例外の実測値が下がったら、記録値も下げます。両指標が既定の上限内に収まったら例外を削除します。
- 関数の削除・改名で不要になった項目は、レビューして修正するまで失敗させます。
- やむを得ない例外追加や解析ツール更新は、制御フローと互換性への影響を説明してレビューします。CI に基準値の自動更新はありません。悪化を隠すために現在の出力を基準値へコピーしないでください。

## CI の結果と失敗

PR・main で `complexity` チェックを実行し、上流の main ルールで必須にします。リリースの検証も `mise run ci` を通して実行します。フォークの必須チェックは各メンテナーが設定してください。

測定が完了すると、cccc の全レポートとポリシー違反を `.complexity/report.json` へ保存します。GitHub は `code-complexity` artifact として14日保持します。この出力は Git の対象外で、ソースリリースに含みません。`complexity:report` は測定結果を見るコマンドで、基準値を強制しません。

ゲートは成功で0、ポリシー違反で1、ツール・設定・レポートの異常で2を返します。バージョン不一致、解析ツールの非0終了、不正・空・不整合なレポート、解析エラーは通過させません。古いレポートは解析前に削除します。実ツールによる回帰テストで、ネスト、兄弟関数ごとの上限、増加・減少・削除、部分的な解析結果と、正常そうな JSON を伴うツール異常を確認します。
