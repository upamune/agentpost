# Scorecard remediation and remaining conditions

[English](scorecard-remediation.md) | [日本語](scorecard-remediation.ja.md)

This records the actionable work behind the score, not a claim of perfect security. OpenSSF Scorecard measures detectable practices; GitHub alert severity on a practice finding does not by itself establish an exploitable application flaw. Keep the findings visible while their prerequisites remain unmet.

| Item                   | Improvement or remaining prerequisite                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fuzzing                | Five fast-check security properties run on every PR/main and daily, with reproducible seeds and shrinking. The first 500,000 generated cases passed. See [coverage and replay](security-checks.md#generative-security-fuzzing).                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Signed releases        | Source archives, checksum file, and manifest receive GitHub OIDC/Sigstore SLSA provenance. Separate build/sign/publish jobs verify the exact five-asset inventory, source digest, workflow identity, and live protected tag before immutable publication. See [release verification](releases.md). A preview alone does not establish a published release.                                                                                                                                                                                                                                                                                             |
| Branch protection      | Main requires PRs, up-to-date branches, resolved conversations, security/CI/formal checks, and CodeQL findings review, with no bypass. Version-tag creation is owner-only, and update/deletion is blocked separately. Independent approving reviews are not yet required because the sole maintainer cannot approve their own PRs.                                                                                                                                                                                                                                                                                                                     |
| Code review            | CODEOWNERS routes changes to the maintainer; [contribution rules](../CONTRIBUTING.md) describe review and testing. A second eligible maintainer is needed before requiring independent approval and code-owner/last-push approval. Historical approvals cannot be created retroactively; agent review is not represented as human review.                                                                                                                                                                                                                                                                                                              |
| Maintained             | The repository was created on 2026-10-24. Scorecard treats repositories younger than 90 days specially. No code change can remove that age condition. Recheck after 2027-01-22, with actual ongoing maintenance.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| OpenSSF Best Practices | [Criteria](https://www.bestpractices.dev/en/criteria/0) require a project entry and truthful statements, including developer security knowledge and past response practices. The repository supplies public source/history, MIT licensing, English/Japanese API/install/operations docs, an issue tracker, private reporting, strict checks, adversarial tests and formal verification. A site account and owner confirmation of human/operational claims remain necessary; no badge or passing status is claimed. The current browser session was signed out; GitHub login requested `user:email` and `read:org`, so registration was left unchanged. |
| Packaging              | Agentpost distributes source for operator-owned Workers and a Bun CLI. It does not publish an npm package or container. Scorecard may not recognize a signed source archive as ecosystem packaging. Do not add a nonfunctional package workflow solely for detection. A registry identity, package name, and supported distribution contract must be chosen before adding a package.                                                                                                                                                                                                                                                                   |

The [public Scorecard result](https://scorecard.dev/viewer/?uri=github.com/upamune/agentpost) is the current source of the numeric score. Requiring nonexistent reviewers, hiding checks, reusing another project's badge, or inventing maintenance history does not improve security. Account administrators can change repository rules; these controls do not defend against complete owner-account compromise. Protect the GitHub and Cloudflare accounts with MFA and restrict administrative access.
